# Структура файлов ЛР2: Где что реализовано

## Пункт 1: SECURITY DEFINER-функции

**Файл:** `lr2_02_security_definer_functions.sql`

**Что реализовано:**
- 3 SECURITY DEFINER-функции:
  1. `app.create_contract()` - создание контракта с валидацией
  2. `app.update_contract_salary()` - обновление зарплаты в контракте
  3. `app.register_recording_session()` - регистрация сессии записи
- Все функции с валидацией входных данных
- Все функции логируют вызовы в `audit.function_calls`
- Установлен безопасный `search_path`
- Выдача прав на выполнение ролям `app_writer` и `studio_manager`

---

## Пункт 2: Тесты прав (≥ 8 кейсов)

**Файл:** `lr2_04_tests.sql`

**Что реализовано:**
- 10 тестовых кейсов (позитивных и негативных):
  1. Успешное создание контракта (позитивный)
  2. Ошибка валидации - несуществующий проект (негативный)
  3. Ошибка валидации - отрицательная зарплата (негативный)
  4. Успешное обновление зарплаты (позитивный)
  5. Попытка DDL неадмином (негативный)
  6. Попытка DML в audit (негативный)
  7. Чтение разрешённых таблиц (позитивный)
  8. Вызов SECURITY DEFINER с невалидными данными (негативный)
  9. Вызов SECURITY DEFINER с валидными данными (позитивный)
  10. Попытка обновления зарплаты в завершённом контракте (негативный)
- Создание RLS политик для `app_owner` (чтобы функции работали)
- Итоговый отчёт по тестам
- Автоматическая проверка наличия функций ЛР2

## Пункт 3: CHECK vs триггер

**Файлы:**
- `lr2_03_check_vs_trigger.sql` - создание тестовых таблиц и функций
- `lr2_06_performance_test.sql` - тест производительности и сравнение

**Что реализовано:**

**В `lr2_03_check_vs_trigger.sql`:**
- Таблица `app.contracts_check_test` с CHECK-ограничениями
- Таблица `app.contracts_trigger_test` с триггером
- Триггерная функция `app.validate_contract_dates()`
- Функция `app.generate_test_contracts()` - генерация тестовых данных
- Функция `app.test_performance_check_vs_trigger()` - тест производительности

**В `lr2_06_performance_test.sql`:**
- Запуск теста на 10,000 строк
- Наглядная таблица сравнения CHECK vs TRIGGER
- Проверка валидации (попытка вставить невалидные данные)
- Вывод статистики и результатов

**Бизнес-правило:**
- `end_date >= signed_date` (дата окончания >= даты подписания)
- Для завершённых контрактов: `end_date <= CURRENT_DATE`

## Пункт 4: Журнал вызовов для SECURITY DEFINER-функций

**Файлы:**
- `lr2_01_function_calls_log.sql` - создание таблицы журнала и функции логирования
- `lr2_02_security_definer_functions.sql` - интеграция логирования в функции
- `lr2_05_demo_function_log.sql` - демонстрация работы журнала

**Что реализовано:**

**В `lr2_01_function_calls_log.sql`:**
- Таблица `audit.function_calls` с полями: call_time, function_name, caller_role, input_params, success, error_message, execution_time_ms, client_ip и др.
- Индексы для быстрого поиска
- Функция `audit.log_function_call()` - SECURITY DEFINER-функция для логирования
- Роль `function_logger` для логирования
- Настройка прав доступа (чтение только для `auditor`)

**В `lr2_02_security_definer_functions.sql`:**
- Все 3 SECURITY DEFINER-функции модифицированы для логирования каждого вызова
- Логирование успешных вызовов (с возвращаемым значением)
- Логирование неуспешных вызовов (с сообщением об ошибке)
- Измерение времени выполнения функций

**В `lr2_05_demo_function_log.sql`:**
- Демонстрация работы журнала вызовов
- Примеры успешных и неуспешных вызовов функций
- Статистика по функциям (общее количество, успешные, неуспешные, среднее время)
- Примеры записей журнала с входными параметрами
- Примеры ошибок
