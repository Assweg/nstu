## Реализованные компоненты

### 1. SECURITY DEFINER-функции

#### `app.create_contract()`
Создание контракта с актёром. Валидирует:
- Существование проекта и актёра
- Уникальность номера контракта
- Положительность суммы контракта
- Корректность дат (end_date >= signed_date)

**Использование:**
```sql
SELECT app.create_contract(
    p_project_id := 1,
    p_actor_id := 1,
    p_contract_number := 'CNTR-2024-100',
    p_role_description := 'Главный герой',
    p_salary_amount := 50000.00,
    p_currency := 'USD'
);
```

#### `app.update_contract_salary()`
Обновление зарплаты в контракте. Проверяет:
- Существование контракта
- Положительность новой суммы
- Статус контракта (нельзя изменять завершённые)

**Использование:**
```sql
SELECT app.update_contract_salary(
    p_contract_id := 1,
    p_new_salary_amount := 60000.00,
    p_reason := 'Повышение за хорошую работу'
);
```

#### `app.register_recording_session()`
Регистрация сессии записи. Валидирует:
- Существование и статус контракта
- Корректность даты (не в далёком прошлом)
- Длительность сессии (0-24 часа)

**Использование:**
```sql
SELECT app.register_recording_session(
    p_contract_id := 1,
    p_session_date := CURRENT_DATE + INTERVAL '1 day',
    p_session_time := '10:00:00',
    p_studio_location := 'Студия А, Москва',
    p_duration_hours := 4.5
);
```

### 2. Журнал вызовов функций

Таблица `audit.function_calls` логирует:
- Время вызова
- Имя функции и схему
- Роль и пользователя, вызвавшего функцию
- Входные параметры (JSON)
- Возвращаемое значение (JSON)
- Успешность выполнения
- Сообщение об ошибке (если была)
- Время выполнения (мс)
- IP-адрес клиента

**Просмотр журнала:**
```sql
SET ROLE auditor;
SELECT * FROM audit.function_calls 
ORDER BY call_time DESC 
LIMIT 10;
```

### 3. Сравнение CHECK vs триггер

Реализовано для бизнес-правила:
- `end_date >= signed_date` (дата окончания >= даты подписания)
- Если статус = 'completed', то `end_date <= CURRENT_DATE`

**Тестовые таблицы:**
- `app.contracts_check_test` - с CHECK ограничениями
- `app.contracts_trigger_test` - с триггерной валидацией

**Запуск теста производительности:**
```sql
SELECT * FROM app.test_performance_check_vs_trigger(10000);
```

### 4. Тесты прав доступа

Реализовано 10+ тестовых кейсов:
- ✅ Успешное создание контракта (позитивный)
- ❌ Ошибка валидации - несуществующий проект (негативный)
- ❌ Ошибка валидации - отрицательная зарплата (негативный)
- ✅ Успешное обновление зарплаты (позитивный)
- ❌ Попытка DDL неадмином (негативный)
- ❌ Попытка DML в audit (негативный)
- ✅ Чтение разрешённых таблиц (позитивный)
- ❌ Вызов SECURITY DEFINER с невалидными данными (негативный)
- ✅ Вызов SECURITY DEFINER с валидными данными (позитивный)
- ❌ Попытка обновления зарплаты в завершённом контракте (негативный)

**Запуск тестов:**
```sql
\i lr2_04_tests.sql
```

## Использование

### Пример: Создание контракта от имени менеджера

```sql
-- Подключаемся как менеджер студии
SET ROLE studio_manager;

-- Создаём контракт (автоматически логируется)
SELECT app.create_contract(
    p_project_id := 1,
    p_actor_id := 2,
    p_contract_number := 'CNTR-2024-NEW-001',
    p_role_description := 'Главный герой',
    p_salary_amount := 45000.00
);

-- Проверяем журнал вызовов
SET ROLE auditor;
SELECT 
    call_time,
    function_name,
    caller_username,
    success,
    execution_time_ms
FROM audit.function_calls
WHERE function_name = 'create_contract'
ORDER BY call_time DESC
LIMIT 1;
```

### Пример: Тест производительности

```sql
-- Запуск теста на 10,000 строк
SELECT * FROM app.test_performance_check_vs_trigger(10000);

-- - Количество вставленных записей
-- - Количество ошибок
-- - Общее время выполнения (мс)
-- - Среднее время на одну вставку (мс)
```

## Безопасность

## Выводы

### CHECK vs триггер:

**CHECK CONSTRAINT:**
- ✅ Проще в реализации
- ✅ Быстрее на уровне БД
- ✅ Автоматически применяется
- ❌ Менее гибкий
- ❌ Ошибки менее информативны

**TRIGGER:**
- ✅ Более гибкий (логирование, сложная логика)
- ✅ Более информативные сообщения
- ✅ Можно использовать в функциях аудита
- ❌ Сложнее в реализации
- ❌ Немного медленнее

**Рекомендация:** Для простых бизнес-правил используйте CHECK, для сложных с логированием - триггеры.
